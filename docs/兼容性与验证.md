# 兼容性与验证

本项目只处理 QEMU IGD OpRegion 到客体固件的交接。没有设备型号表，表示程序通过 ROM 所属设备取得 PCI 接口，不表示任意 Intel 显卡都已兼容。

## 运行条件与实现边界

| 项目 | 条件或行为 |
|---|---|
| 客体固件 | X64 OVMF，按 PCI Option ROM 路径加载 EFI 并提供所属设备的 `PCI_IO` |
| 设备绑定 | 使用者将 ROM 绑定到目标 Arrow Lake 核显；入口不做厂商、设备类别或型号筛选 |
| 数据来源 | QEMU `etc/igd-opregion`；一个客体只使用这一份 IGD 数据源 |
| 数据大小 | 8 KiB～1 MiB，完整复制扩展区；超出范围拒绝交接 |
| VBT 布局 | 支持内嵌 VBT 和 OpRegion 2.1+ 的相对 RVDA 外置布局；不支持 2.0 的绝对地址外置布局 |
| 校验 | 检查 OpRegion / VBT / BDB 的签名、声明大小和引用范围；不解析所有显示配置业务块 |
| VBT 校验和 | 非零字节和仅作 DEBUG 诊断，保留原始数据；结构或范围错误仍拒绝 |
| 客体内存 | 完整分配落在 4 GiB 以下，标记为 ACPI NVS，供后续驱动持续使用 |
| 已有 ASLS | 非零时保留原值，返回 `EFI_ALREADY_STARTED`；不验证该旧地址指向的数据 |
| 发布失败 | 写 ASLS 前失败可释放内存；一旦尝试写入，即使失败也保留内存，避免设备持有悬空地址 |
| 固件签名 | 构建产物未签名；能否被加载取决于具体固件策略 |

GOP 输出、SR-IOV、GPU BAR / stolen-memory 配置、宿主 VFIO 配置、Windows 驱动及主板 BIOS 更新均在项目范围之外。辅助 ROM 不能代替这些环节。

## 验证方法与结果

| 检查 | 已通过结果 | 能说明什么 |
|---|---|---|
| Mac 构建 | RELEASE 和 DEBUG 均生成 X64 EFI / ROM | 该构建组合能够产出目标格式的文件 |
| C 数据测试 | 23 个用例通过，ASan / UBSan 无报告 | 覆盖所构造的格式、边界和错误分支 |
| ROM 格式测试 | 8 个用例通过 | 覆盖容器字段、PE 边界和载荷一致性 |
| 真实数据校验 | 15,872 字节 OpRegion 通过校验 | 该平台数据布局被校验器接受 |
| 客体启动 | RELEASE ROM 两次完整关机后启动均通过 | 两次客体启动完成固件交接；不是宿主断电重启测试 |
| Windows 设备状态 | 两次均为 `OK`，`ConfigManagerErrorCode = 0` | 该驱动在该环境中接受设备初始化 |
| 基本 GPU 操作 | 每次 64 轮，共 16,384 像素回读全部匹配 | 显式选中的 Intel 硬件适配器能够执行这些 D3D11 操作 |
| 数据交接 | ASLS 指向有效 OpRegion，客体 VBT 与 QEMU 源副本逐字节相同 | ROM 没有截断或改写这份 VBT |

D3D11 检查显式选择 Intel `8086:7d67` 硬件适配器，使用 feature level `11_1`，不回退到 WARP 软件渲染。每轮对 16×16 的 RGBA32F 离屏纹理清屏，通过 GPU `CopyResource` 拷贝到可读资源，再 `Map` 回读比较。它验证基本 GPU 操作，无法代表游戏性能、完整渲染功能或长期稳定性。

测试客体报告 Secure Boot 已启用，同时成功启动了这份未签名 ROM。这个观察仅适用于该固件及策略组合，不能推导为所有启用 Secure Boot 的 OVMF 都会加载未签名 Option ROM。

尚未验证：其他 PCI ID 或主板固件、其他 QEMU / OVMF 版本、Intel Mac 构建、Linux 客体、长时间 GPU 压力、视频编解码、外接显示器、睡眠恢复和多核显环境。DEBUG ROM 只完成构建与格式检查，没有完成上述硬件运行验证。

## VBT 非零校验和案例

已验证平台提供的 VBT 声明长度为 7,323 字节，checksum 字段为 `0xCA`，按声明长度逐字节求和模 256 的结果为 `0xDC`。这个结果偏离通常期望的零校验和。

启动时 QEMU 的源 VBT 与客体中的副本逐字节相同，说明异常最迟在进入客体前已经存在；Windows 驱动仍报告设备正常并通过上述硬件检查。异常的具体来源尚未确定，不能据此声称这种数据对所有驱动都有效。

因此本项目保留原始 VBT，将校验和异常作为 DEBUG 诊断，不把它单独作为拒绝条件，也不自动修改 checksum 字段。签名、声明长度和引用范围仍须满足检查。Linux 7.0 的 [`intel_bios_is_valid_vbt()`](https://github.com/torvalds/linux/blob/028ef9c96e96197026887c0f092424679298aae8/drivers/gpu/drm/i915/display/intel_bios.c#L3064-L3106) 同样没有读取或强制验证 `vbt_checksum`；这个源码依据不证明异常根因，也不替代对具体显示功能的测试。

## 如何报告新的兼容性结果

报告时给出目标 PCI ID、宿主与 QEMU / OVMF 版本、客体系统和驱动版本、构建配置及 ROM SHA-256，并区分“格式检查通过”“设备状态正常”和“实际硬件操作通过”。失败报告还应说明是否确实提供了 `etc/igd-opregion`、ROM 是否绑定到目标设备、原有 ASLS 是否非零。

公开日志前删除 IP、MAC、VM UUID、设备实例路径等机器信息。原始 OpRegion / VBT 属于平台固件数据，先确认是否需要及是否适合公开；不要把它当作仓库必备样本上传。仓库仅包含合成数据测试，不包含真实平台固件样本或私有部署日志。
